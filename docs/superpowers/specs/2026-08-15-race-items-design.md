# Расы и субрасы предметами

Дизайн переезда рас и субрас из `module/constants/races.mjs` в компендиум-библиотеку
предметов, чтобы персонажа можно было собирать переносом расы на лист.

Читается вместе с [планом архитектуры](../../architecture-plan.md): это продолжение
этапа 4 «Контент в данные» тем же приёмом, каким туда уехали Архетипы и Родные миры.

## Зачем

Раса сегодня — 587 строк кода: 18 рас, 14 субрас с данными, 138 расовых Черт.
Чтобы добавить расу или поправить бонус, нужно править `.mjs` и выпускать релиз.
Архетипы этот путь уже прошли: они лежат в компендиуме, ГМ правит их мышкой, и
система читает библиотеку, а не константы. Расы — третий повтор того же приёма,
плюс новая возможность: перенести расу на лист персонажа и получить готовую основу.

## Что выяснилось до начала

Пять фактов, найденных при разборе; на них опираются решения ниже.

**Рейтинг параметрических Черт не работает.** Черта-шаблон в паке — «Unnatural
Strength / Сверхъестественная Сила (X)» с жёстко зашитым ActiveEffect `+1`.
Конструктор при выдаче ставит `system.rating = 4`, но эффект не пересчитывает, и
рейтинг остаётся только в тексте. Проверены все параметрические Черты пака:
величина эффекта совпадает с полем `rating` в 6 случаях из 6 — Демонический (1),
Страх (2), Машина (3), Естественная Броня (2), Сверхъест. Сила (1), Сверхъест.
Стойкость (1). Значит «эффект равен рейтингу» — не догадка, а способ, которым пак
заведён. Это живой баг и сегодня: ГМ, перетащивший «Размер (X)» с рейтингом 2,
получает +1.

**`AELDARI_RACES` посимвольно совпадает с группой «Аэльдари»** из `RACE_GROUPS`.
Одно поле `group` на предмете заменяет обе константы.

**67 расовых Черт из 102 уникальных уже лежат в паке `traits`** (сверка по имени с
нормализацией скобок). Не хватает 35 — в основном больших повествовательных:
«Эльдарское Тело», «Тёмная Душа», «Через Боль».

**У листа персонажа нет своего `_onDrop`** — он полагается на поведение
`ActorSheetV2` по умолчанию, а оно просто создаёт предмет на акторе. Брошенная на
лист раса легла бы мёртвым грузом.

**Шесть полей расы никто не читает** вне самого `races.mjs`: `size`, `bonusPoints`,
`charShift`, `fateRoll`, `skillsNote`, `adaptations`. Это книжная справка. Переносим
как текст на лист расы, чтобы контент не пропал, но считать по ним ничего не будем.

## Решения

| Решение | Выбор | Почему |
| --- | --- | --- |
| Глубина замены | Предмет-носитель + `system.race` как ключ-зеркало | Предикаты правил, замки папок, CSS-темы, элитные архетипы и `reqRace` читают ключ и продолжают работать без правок |
| Черты расы | Ссылками через Конструктор (`kind:"trait"`) | «Проворный» правится один раз для четырёх рас; 67 Черт уже в паке |
| Рейтинг | Чиним в Конструкторе отдельной задачей | Одна точка, чинит и живой баг ручной выдачи; пак не трогаем |
| Остальное содержимое | Числа полями схемы, выдачи Конструктором | Стартовые 25/30 — не бонусы, а базовые значения в пустые поля |
| Структура | Два типа: `race` и `subrace` | Схемы честнее: у субрасы своя цена в опыте, бог и снимаемые Черты |
| Старые персонажи | Не мигрируем, даём кнопку | Сопоставление Черт по именам ненадёжно: игроки их правили и переименовывали |

## Архитектура

### Типы и пак

Два типа предметов в одном компендиуме `races` (`packs-src/races/` → `packs/races`,
объявление в `system.json` как у `traits`; подтипы в объявлении пака не
ограничиваются — `traits` уже хранит Черты и элитные архетипы вперемешку).

Внутри: 18 записей `race` в папках по группам (Люди / Отродия / Аэльдари / Другие
Ксеносы) и 16 записей `subrace` в своей папке, у каждой — ключ родителя.

Про число 16: `SUBRACES` перечисляет 16 меток, а `SUBRACE_DATA` содержит 14 —
у `eldanar` (Азуриане) и `grayman` (Полуэльдар) данных нет вовсе, есть только
название. Генератор обязан завести и их: запись с именем, ключом и родителем, без
механики. Иначе они молча исчезнут из списка субрас на листе, а сегодня игрок их
там видит и может выбрать. Пустая запись честнее пропажи — её видно и в неё можно
дописать книгу.

`RaceData` — `module/data/item/race.mjs`:

| Поле | Тип | Кто читает |
| --- | --- | --- |
| `key` | String | зеркало `system.race`, `reqRace`, предикаты, CSS-класс `wh-race-*` |
| `group` | String | группы в списках **и** признак аэльдари |
| `chars` | Object | `applyRace` → стартовые значения в пустые поля |
| `bonusRolls` | Number | Мастер создания |
| `skills` / `gear` / `talents` | String | Мастер: разбор текстовых пакетов |
| `description` | String | лист расы, слот в шапке |
| `hasGeneSeed` | Boolean | органы Геносемени Астартес |
| `pastRaces` | Array | Прошлое Иннари и Арлекина |
| `size`, `bonusPoints`, `charShift`, `fateRoll`, `skillsNote`, `adaptations` | — | никто: книжная справка, только показ |
| `bookSource` | String | как у всех библиотечных записей |

`SubraceData` — `module/data/item/subrace.mjs`: `key`, `parent`, `cost` (в опыте),
`effect`, `god`, `charMods`, `talents`, `removesTraits`, `description`, `bookSource`.

Чего в схемах нет намеренно:

- **`traits`** — Черты живут записями `flags.warhammer-dbc.mechanics`. Поле схемы
  завело бы второй источник правды о том же.
- **`rules`** — `ASTARTES_RULES` остаются кодом в `module/rules/library/`.
  `registerRuleSource("race")` вместо `RACES[key]?.rules` смотрит в карту
  `{ astartes: ASTARTES_RULES }`. Машинные правила остаются там, куда их положил
  этап 3 плана; переносить их в дроплисты значило бы переделывать сделанное.

### Разделение модулей

- `module/apps/race-library.mjs` — **только чтение**: кэш пака полными документами
  по образцу `apps/archetypes.mjs`, `raceEntries()`, `subracesOf(key)`,
  `isAeldariRace(key)`, откат на константы, пока пак не прочитан.
- `module/apps/races.mjs` — **только применение**: `applyRace`, `applySubrace`,
  `clearRace`, плюс уже живущие там Прошлое и Легион.

Граница простая: библиотека не меняет акторов, применение не читает пак напрямую.

## Поток применения

Три входа, одна дорога.

1. **Слот в шапке листа** — клик открывает пикер рас из библиотеки.
2. **Дроп предмета на лист** — `_onDropItem` перехватывает типы `race`/`subrace` и
   уводит в применение; обычное создание предмета не выполняется.
3. **Мастер создания** — зовёт те же функции.

Плюс страховка: хук `createItem` ловит расу, появившуюся на акторе мимо листа
(макросом, скриптом, копированием). Зацикливания нет — хук молчит, если у предмета
уже стоит флаг `originGrant`, а его ставит сам `applyRace`.

`applyRace(actor, key)`:

1. `clearRace(actor)` — снять прежний носитель и всё выданное через
   `clearGrantedBy(actor, "race", item)` из `origin-shared.mjs`.
2. Пустой ключ — выйти: раса снята.
3. Взять запись из кэша библиотеки.
4. Положить embedded-копию с флагом `originGrant: "race"` → штатный `createItem` →
   `applyItemMechanics` выдаёт Черты, таланты и навыки Конструктора.
5. Записать `system.race = key`, обнулить `system.subrace`.
6. `chars` → в **пустые** поля `system.characteristics.*.base`. Единственное, что
   делает код, а не Конструктор: «только в пустые» — правило создания персонажа, а
   не эффект предмета, и ГМ не должен ломать его дроплистом.
7. `hasGeneSeed` → органы Геносемени.

`applySubrace(actor, key)` — тем же порядком с тегом `subrace`, плюс
`removesTraits`: субрасы друкхари отменяют часть расовых Черт.

Проверки при дропе:

- **раса** — принимается всегда; стоявшая прежде снимается со всем выданным;
- **субраса** — только если `parent` совпал с текущей расой; иначе отказ с
  пояснением («Мандрагора — субраса Друкхари, а у персонажа Азуриане») и лист не
  меняется; расы нет вовсе — «Сначала выберите расу»;
- **смена расы** снимает субрасу: она относилась к прежней расе.

Три вещи чинятся попутно: повторное применение перестаёт плодить дубли (сегодня
кнопки «Применить Иннари/Арлекина» при втором нажатии создают Черты заново);
удаление носителя из списка предметов уносит выданное готовым общим хуком
`deleteItem` по `grantedByItem`; Прошлое получает свой тег `racePast` и снимается
отдельно от расы.

Двойного счёта не возникает по построению: предмет-раса не несёт
`characteristic`-записей вовсе, числа приходят только Чертами, а `chars` пишутся
разово в пустое поле.

## Лист персонажа

Две ячейки шапки заменяются карточками-слотами (приём Pathfinder 2e).

Пустой слот — пунктирная рамка «перетащите расу», клик открывает пикер из
библиотеки (образец готов — `elite-picker.mjs`). Заполненный — иконка, имя, кнопка
«открыть» (лист расы: описание, характеристики, Черты в Конструкторе) и крестик
(`clearRace`). Слот подсвечивается на `dragenter`, но бросить можно в любое место
листа.

У слота есть третье состояние — **ключ есть, носителя нет**. В нём окажутся все
персонажи, созданные до этой работы: `system.race` у них заполнен, предмета не
существует, и мигрировать их мы решили не автоматически. Такой слот показывает
название расы по ключу (из библиотеки) приглушённо, с подписью «не применена» и
кнопкой «Применить» — она зовёт `applyRace(actor, key)` для уже стоящего ключа.
Это и есть обещанная кнопка ручной миграции: она на виду ровно у тех персонажей,
кому нужна, и не мозолит глаза остальным. Пока её не нажали, лист работает
по-старому: всё, что читает ключ, читает ключ.

В контекст добавляются `context.raceSlot` и `context.subraceSlot`
(`{ id, name, img, key }` или пусто), действия V2 — `racePick`, `raceOpen`,
`raceClear` и такие же для субрасы. Селекты уходят вместе со своим атрибутом
`name`, чем решается нынешняя двойственность: сейчас у `.race-select` есть и
`name="system.race"`, и слушатель, то есть форма при `submitOnChange` пишет поле в
обход применения. Образец рядом — у `.arch-select` атрибута `name` нет.

Остаются в шапке рядом со слотами, потому что это не раса: Дом Навигатора, Прошлое
Иннари и Арлекина (селекты — это ссылка на другую расу, а не второй носитель),
Происхождение аэльдари, Геносемя и Культура Астартес. Свободный ввод субрасы для
рас без субрас остаётся текстовым полем: за произвольным текстом предмета нет.

## Мастер создания

Единственное место, где расу читают до того, как актор её получил: предпросмотр
суммы характеристик, бонусные броски, распределение очков.

Меняется мало: `resolveCreation`, `creationCharSum`, `creationBonusRolls` берут
записи из библиотеки вместо `RACES`; кэш синхронный, поэтому сигнатуры и диалог не
переписываются. Списки в диалоге — по полю `group`, `subracesOf`, `isAeldariRace`
вместо трёх констант.

Меняется по существу одно место: сейчас мастер выдаёт расу сам
(`createTraits(race?.traits)`, `createTraits(sub.traits)`,
`applyStartingTalents(race?.talents)`). Это второй путь выдачи, и он разошёлся бы с
первым при первой правке. Заменяется вызовами `applyRace` / `applySubrace`.

Порядок фиксируется явно:

1. `applyRace` — носитель, Черты, таланты, навыки; `chars` в пустые поля;
2. `applySubrace` — то же плюс `removesTraits`;
3. мастер записывает **итоговые** характеристики поверх: его сумма учитывает
   архетип, броски и распределение, расовые `chars` в ней лишь слагаемое;
4. `grantCreationSkills` / `grantCreationGear` — как сейчас, разбор строк
   `skills`/`gear` из предмета.

Шаг 3 обязан идти после 1–2: иначе `applyRace` увидит непустые поля и молча не
впишет ничего.

Повторный прогон мастера получает честный откат вместо нынешней дедупликации по
имени: `clearRace` снимает прежний носитель со всем выданным, и Черты не
задваиваются, даже если игрок их переименовал.

При недоступной библиотеке работает откат на константы, поэтому
`test/apps/creation.test.mjs` (314 строк) остаётся зелёным без правок. Это критерий
готовности, а не предположение.

## Тесты

Главный — сквозной, на числах: Астартес после `applyRace` имеет +4 к бонусу Силы,
+4 к Стойкости и Размер 1; Азуриане — +4 Ловкости и Восприятия. Сегодня эти числа
приходят из констант через `charBonusValue`, после переезда — из Черт по ссылке с
пересчитанным рейтингом. Зелёный тест и есть определение «переезд состоялся».

## Порядок работ

1. **Фикс рейтинга в Конструкторе** — отдельной задачей-багом (`discovered-from`).
   Первым: без него ссылки на параметрические Черты бессмысленны.
2. Типы `race`/`subrace`, схемы, листы предметов, регистрация в семи точках, пак в
   `system.json`.
3. 35 недостающих Черт в паке — контент, параллельно со вторым.
4. Генератор `tools/races-to-pack.mjs`, 34 записи, сверочные тесты.
5. Библиотека-кэш, перевод восьми потребителей.
6. Применение: `applyRace`/`applySubrace`/`clearRace`, хук `createItem`,
   `_onDropItem`.
7. Слоты в шапке, пикер рас, стили.
8. Мастер создания на общий путь.
9. Документация: переписать `docs/how-to-add-race.md`, отметить этап в плане.

Зависимости: 1 → 4, 2 → 4, 3 → 4, 4 → 5 → 6 → 7 и 8.

## Границы

- Машинные правила остаются кодом в `module/rules/library/`, в данные не переезжают.
- Существующие персонажи не мигрируются автоматически: `system.race` остаётся
  ключом, всё на листе читает его, носитель появляется при следующей смене расы или
  по кнопке «Применить расу».
- Родной мир и Архетип под слоты не переделываются. Панель из четырёх слотов —
  отдельное решение, если захочется.
- `module/constants/races.mjs` не удаляется: остаётся откатом, как
  `constants/archetypes.mjs`. Удаление — отдельное решение потом.
- jQuery в остальных модулях вкладок (wdbc-z0z) не трогаем, кроме обработчиков
  расы, которые и так переписываем.

## Риски

| Риск | Как ловим |
| --- | --- |
| Числа разъехались при переезде | сквозной тест Астартес и Азуриан |
| Рейтинг не применился | тест Конструктора, задача идёт первой |
| Пак не прочитан (тайминг `ready`) | откат на константы + тест на откат |
| Дубли Черт при повторном применении | тест повторного вызова `applyRace` |
| Дроп расы прошёл мимо применения | `_onDropItem` **и** хук `createItem`, защита флагом |
