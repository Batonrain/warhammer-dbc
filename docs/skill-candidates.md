# Кандидаты в скиллы/агенты

Накопитель находок с ретроспектив конца сессии. Ретроспектива сама НЕ заводит
новые скиллы и агентов — находка сперва попадает сюда строкой. Кандидат
превращается в реальный скилл/агента только на **третьем** появлении в этом
файле (по сути одной и той же находки), не раньше. Правки уже существующих
скиллов/агентов этот фильтр не касается — под него подпадает только создание
новых сущностей.

Формат строки: `дата — суть находки — источник (сессия/файл/задача)`.

## Накопленные находки

- 2026-08-31 — при каждом новом предикате (predicates.mjs) или rule source (sources.mjs) приходится вручную чинить 3 захардкоженных счётчика в тестах (test/rules/collect.test.mjs — список источников, test/rules/scaffold.test.mjs — `toHaveLength(N)` предикатов, test/rules/predicates.test.mjs — карта эталонных значений); за сессию повторилось на каждой из ~3 новых сущностей — кандидат на тест, который считает сам (`Object.keys(...).length`), а не хардкодит число — источник: сессия wdbc-sk8s (Avatar of Slaughter / Adjutant / Dread Wail).
- 2026-08-31 — задача «механизм + 3-5 показательных записей из большого реестра (63 способности с ценой)» потребовала ручного двухшагового кросс-поиска (grep текста реестра на паттерн цены → cross-reference с capabilityKey, реально выданными в packs-src, с фильтром «это правда трата, а не начисление») прежде чем нашлись подходящие образцы; кандидат на скрипт/агента «найди N живых показательных записей реестра X по текстовому паттерну» — источник: сессия wdbc-1dc8 (Цена Возможности).
- 2026-08-31 — временный баф актора/техники через встроенный (embedded) Item вместо правки движка агрегации работает сразу в существующем конвейере: `vehicleTrait` с `system.effects.{spdMod,manoeuvreMod}` читает `rules/vehicle.mjs::prepareVehicleDerived` как обычную Черту техники, `forcefield` с `currentRating/shieldType/shieldNature` читает `combat/damage.mjs::_rollActiveShield` как обычный щит-предмет — реюзабельный паттерн «дать временный бонус/щит без нового кода в агрегации», сработал дважды в одной сессии (Song of Swiftness, Preservation) — источник: сессия wdbc-sk8s (Певцы Кости).
- 2026-08-31 — книжная фраза «Мастер на Пути X» у Таланта проверяется готовой формальной системой, не нужно искать отдельный механизм: `module/constants/aeldari-paths.mjs::AZURIANE_PATHS` хранит путь по ключу (напр. `bonesinger`) с градациями novice/next/master/lost, актёр хранит `system.paths: [{key, grade}]` — проверка `paths.some(p => p.key === X && p.grade === "master")`. Путь уже был в проекте (архетип-Происхождение ссылался на него текстом), просто раньше не проверялся кодом ни у одного Таланта — источник: сессия wdbc-sk8s (Bone Song/Preservation/Song of Swiftness).
- 2026-08-31 — `rescaleTraitByRating` (module/apps/mechanics.mjs) для шаблонов-Черт «(X)» меняет только значения, РАВНЫЕ базовому `rating` (простой `swap`, не пропорция) — работает для позитивных бонусов (Regeneration/Unnatural WP), но не для отрицательного штрафа (число со знаком минус не совпадает с положительным rating). Решилось не обходом эвристики, а набором из N фиксированных экземпляров под встреченные магнитуды (Daemonic Dread −5/−10/−15/−20) — кандидат на заметку/проверку при следующей идее «шаблон-Черта с отрицательным рейтингом», не обязательно на скрипт — источник: сессия «Дуум», wdbc-995w (Daemonic Presence).
- 2026-08-31 — `js.configs.recommended` (eslint) целиком непригоден для этого репозитория «как есть»: даёт 3751 новую находку (в основном `no-empty` на пустых catch-блоках) в коде, который никто чинить не просил. Правила из пресета, реально нужные под конкретную задачу, брать точечно в объект `rules` (проверено на no-dupe-class-members/no-dupe-keys/no-unreachable/no-fallthrough — с ними 0 ошибок), а не подключать пресет целиком. Заодно `no-dupe-keys` сразу поймал 2 живых дубля ключей объекта (test/data/actor-schemas.test.mjs, module/apps/creation.mjs) — точечные правила из recommended стоит рассматривать не только как гигиену, но и как рабочий детектор багов. Кандидат на заметку в память, если всплывёт снова — источник: сессия «Дуум», wdbc-swzz (пять дешёвых стражей).
- 2026-08-31 — при аудите «зашитое сравнение имени предмета → itemHasName» полезно отличать substring-regex (`/Слово/i.test(name)`) от anchored/exact-сравнения (`Set.has(exact)`, `name.startsWith(...)`): первое почти всегда уже работает на реальных бигвальных именах пака (подстрока находится где угодно), второе — часто уже сломано молча, потому что реальное имя вида «English / Дар: Русское» не совпадает с ожидаемым форматом целиком. За сессию нашлись 2 таких скрытых бага разом (character.mjs::giftNames Set-сравнение, possession.mjs::name.startsWith) — оба ни разу не срабатывали на реальных Дарах Одержимого. Кандидат на чек-лист/скрипт «прогнать существующий regex/exact-match кусок против реальных имён из packs-src ДО переноса на itemHasName, не полагаясь на то, что перенос ничего не сломает» — источник: сессия «Дуум», wdbc-rc5z (character.mjs: 8 матчей по имени).
- 2026-08-31 — перенос таблицы доступа/списка ключей из кода в поле схемы предмета (по образцу RACE_RULES) требует держать в уме ДВА места записи данных одновременно, если у механизма есть fallback-константа на случай пустого кэша компендиума (`archetypeEntries() = CACHE || ARCHETYPES`) — забыть синхронно обновить fallback-константу молча ломает поведение ровно в тестах без Foundry (они и есть основной потребитель fallback-пути). Тот же класс ловушки, что уже отмечен для source-name-sync (см. doombc-mechanics-source-name-sync-test), но конкретно для «таблица доступа как поле схемы» — источник: сессия «Дуум», wdbc-t9ei (Друкхари/Сслит архетипы).
- 2026-08-31 — поиск «мёртвых экспортов» по всему модулю: наивный `grep -rl <имя>` (файлы, где встречается) даёт массу ложных срабатываний на константах/функциях, используемых только ВНУТРИ своего же файла (например, косвенно через другую функцию) — они не мертвы, просто не импортируются наружу. Рабочий фильтр — считать СУММАРНЫЕ вхождения имени по всему репозиторию (все .mjs/.hbs/.json/.md, включая тесты) одним проходом (node-скрипт, не по каждому имени отдельным grep — иначе на ~2000+ экспортов таймаут); кандидат на удаление только если вхождение ровно одно (сама строка объявления). После удаления первой партии — прогнать скан повторно: удаление живой функции часто осиротяет константу/импорт, которую она была единственным потребителем (каскад). Кандидат на переиспользуемый скрипт/агента «найти по-настоящему мёртвые экспорты в JS-модуле» — источник: сессия «Дуум», wdbc-xtei (Мёртвый код волны-2).
- 2026-08-31 — реализация фичи на НЕЗНАКОМОМ куске Foundry Canvas API (тут — Grid API v2: `canvas.grid` теперь чистая геометрия, рендер/подсветка клеток переехали в `canvas.interface.grid`/GridLayer) уткнулась в то, что в проекте нет локального клиентского исходника Foundry для сверки сигнатур — пришлось идти в WebFetch/WebSearch по `foundryvtt.com/api/**` и GitHub-обсуждениям миграции, по кусочкам восстанавливая точные сигнатуры (`measurePath` cost-колбэка, `highlightPosition` — пиксели top-left, не offset i/j). Кандидат на приём/агента «перед первым использованием незнакомого метода `canvas.*`/`foundry.*` — сначала WebFetch официальных API-доков этой версии, не гадать по аналогии со старым API» — источник: сессия «Дуум», wdbc-rgi8 (подсветка достижимых клеток движения).
- 2026-08-31 — новому Region-поведению не обязательно быть одним составным behavior: два НЕЗАВИСИМЫХ `RegionBehaviorType` спокойно вешаются на один и тот же Region-документ (Гравитонное = свой мелкий behavior только на усыхание радиуса + уже готовый `DifficultTerrainBehaviorType` сайдкаром с `extraMod:-30`) — так переиспользуется весь существующий движок (тест A+0, HUD-кнопка, `getTerrainInfoForToken`) без единой правки в нём. По той же находке — прежде чем писать новую механику «зона с готовым списком свойств», стоит заглянуть в уже существующие константы-таблицы (`TERRAIN_PROPS` в difficult-terrain.mjs уже содержал чекбокс «Дым или туман», не пришлось изобретать для свойства Дым ничего нового, только программно включить существующую галочку) — источник: сессия «Дуум», wdbc-wlwf (Дуга/Гравитонное/Насквозь/Дым).
