## 3. Три гейта (обязательны перед «готово»)

```bash
npm test              # vitest, без живой Foundry
npm run lint          # eslint; ошибок быть не должно, предупреждения терпимы
npm run packs:build   # сборка компендиумов из packs-src/
```

- В отчёте — **вывод** команд, а не память о нём.
- `packs:build` обязателен, если тронуты `packs-src/` или `tools/`: CI делает
  круговорот сборка → извлечение (`packs:unpack`) и падает при расхождении
  `git diff -- packs-src`.
- Собирать паки **только на `main`** и при закрытом мире Foundry: сборка
  стирает папку пака; правки, сделанные в игре и не снятые `packs:unpack`,
  затрёт (защита — отметка `packs/.pack-stamp`; принудительно —
  `npm run packs:build -- --force`). Остановка/запуск мира — делает сам
  Сергей (нужен админ-пароль Foundry, которого у ассистента нет).
- Расчёты актора (`module/documents/actor.mjs`) тестами не покрыты — говорить
  прямо и просить Сергея сверить в игре, называя, что именно смотреть.
- Подход: сначала падающий тест, потом код; данные паков тестируются так же
  строго, как код (схема против настоящих JSON из `packs-src`, не выдуманных).
- Все остальные npm-скрипты: `packs:unpack`, `icons:build`, `worktree:check`
  (`tools/worktree-guard.mjs` — защита общей рабочей копии),
  `git:merge-main` (`tools/merge-main.mjs`).

## 6. Конвейер: от правки до релиза

```
правка (main, локально) → 3 гейта → ветка pr/<тема> от origin/main
  → PR (Derbius → main) → CI «Check» зелёный → мердж Batonrain
  → автоматически: Release (тег vX.Y.Z, system.json + system.zip в GitHub Release)
```

- **Работа идёт прямо в локальной `main`** (общая рабочая копия), PR
  собирается отдельным шагом тематическими ветками от `origin/main`.
  С 03.09.2026 коммит → мердж → гейты → пуш → PR → CI — автоматический
  последний этап сессии (`git-scribe`); без подтверждения на каждом шаге, но
  финальный конвейер по команде «Конец сессии» (см. раздел 4).
- **Ветку PR отрезать без checkout в общей копии** — через отдельный
  `git worktree` в `Temp`: checkout в общей копии откатит дерево параллельной
  сессии.
- **Запрещено** (и в `settings.json` deny): `git rebase`, `reset --hard`,
  `clean -f`. Не использовать `git stash` на общей `main` для «сверки до/после»
  — сравнивать через `git diff`/копию файла. Перед `git merge origin/main`
  сверить пересечение диффа с `git status` (сосед может править тот же файл).
  Перед коммитом смотреть `git diff --cached` — чужое уже застейдженное не
  видно в `git status`.
- **PR не вливать самому.** Довести до открытого PR с зелёным CI; после
  мерджа — `npm run git:merge-main` (не голый `git pull`/`git merge`,
  см. `dbc-workflow`, шаг 13). Включить Auto-fix на PR сразу, без вопроса
  (постоянное правило Сергея).
- **CI** (`.github/workflows/check.yml`, на PR и push в `main`, Node 22):
  `npm ci` → `npm run lint` → `npm test` → `packs:build` + `packs:unpack` +
  `git diff --exit-code -- packs-src`.
- **Релиз** (`release.yml`, на push в `main`): берёт последний тег, поднимает
  patch, публикует. `#minor` / `#major` в заголовке PR — другой инкремент.
  Не запускается, если PR трогает только `README.md`, `LICENSE`,
  `.github/`, `books/`, `docs/`, `test/`, `package*.json`, `eslint.config.mjs`.
  Ручной запуск: GitHub → Actions → Release → Run workflow.
- Описание PR заканчивать блоками: «Проверить в Foundry (очередь testing)» и
  «Разобрать (не автоматизировано)», если в облачной сессии нет доступа к bd /
  Sahara.

Самые важные по смыслу — в разделе 9.

## 8. Живая Foundry и параллельные сессии

- Один живой мир, один процесс (порт 30000), один Chrome/тестовый ГМ. Логин
  для живых тестов: пользователь **«Пантеон»**, без пароля — указывать явно в
  промпте `live-tester`.
- Живые проверки — **только** через агента `live-tester` в фоне; одновременно
  **один** тестер (четыре параллельных мешали друг другу). Лок `wdbc-a4l` он
  берёт сам. Запустил и не жди — он сам заведёт баг, если найдёт.
- Всё, что не проверено живьём, обязано уйти задачей в очередь `testing`
  (bd, самодостаточный текст: что сделано, где, что прощёлкать, чего ждать).
  «Проверено только тестами» без такой задачи — незаконченная работа.
- Файлы: перечитывать прямо перед правкой; для существующих файлов — `Edit`
  с точечным диффом, не `Write` целиком (затирает чужую правку молча).
- Массовые скрипты правок `packs-src` запускать из корня репозитория, а не из
  Temp (иначе блокируются). Скрипт — файлом через Write, не heredoc и не
  `node -e` (на Windows ломаются `\n`, `\1`, `\s` и кириллица). `python3` в
  bash на этой машине может молча зависнуть — использовать node/Edit.
- Не строить поверх чужого незакоммиченного WIP при активной параллельной
  чистке: перед коммитом сверять `git show origin/main:<файл>`.

## 9. Главные ловушки проекта (выжимка из `AGENTS.md` и памяти)

1. **Id документа/папки — ровно 16 символов `[A-Za-z0-9]`.** Придуманный
   15-символьный id проходит все гейты, но убивает живой мир (пустая страница,
   `game.ready === false`). Живёт в четырёх местах: `_id`, `_key`, имя файла,
   поле `folder` у детей.
2. **Кириллица в regexp:** `\w` и `\b` без флага `u` не видят русские буквы;
   запись тихо уезжает в «нераспознанное». Использовать `\S`/`[а-яёА-ЯЁ]`.
3. **«Система этого не умеет» — сначала проверить:** `module/data/<тип>.mjs`,
   `blankEntry` в `module/apps/mechanics.mjs`, `grep` по `packs-src/`,
   `docs/systems-map.md`. Четыре ложных вывода уже были.
4. **Поле, забытое в схеме `TypeDataModel`, тихо пропадает** при первой
   правке предмета в игре. Проверять на настоящих JSON из `packs-src`.
5. **Фикстура теста должна совпадать с реальным JSON пака** — зелёный тест не
   доказывает, что фича жива.
6. **Механика предмета — одна модель:** `flags.warhammer-dbc.mechanics`
   (Конструктор). `reqBlocks`/`mechBlocks` сняты; не воскрешать. Не заводить
   новых читателей `system.effects.*`. Ключи эффектов — только из
   `module/constants/effect-keys.mjs`. Флаг `migratedEffect` — не пометка
   «сделано».
7. **Миграции не все идемпотентны** — повторный прогон ломает (инверсия знака,
   «надето»). Новый проход — отдельным ключом, не повышением `VERSION`.
   Несвязанные токены мигрировать в пределах своей дельты.
8. **Цикл импортов в `module/rules/`:** файл-источник правил не должен тянуть
   ничего, что ведёт обратно к `sources.mjs` (вешает загрузку, а не падает);
   стережёт `test/rules/source-registry-acyclic.test.mjs`.
9. **Пак-текст ≠ книга:** поле пака часто урезанный пересказ. Сверять с
   `sources/` по всей книге (определение бывает в чужой главе и уже
   реализовано). Порядок имён в паках — всегда «Английское / Русское».
   Сверка по `core.json` не трогает Друкхари/Аэльдари/Арлекинов — у них своя
   книга.
10. **Числа в тикетах не проверены:** мерить до правки (на эпике wdbc-g6cb 5 из
    7 диагнозов не подтвердились); смотреть знак, а не только величину.
11. **Агентам, правящим `packs-src`, прямым текстом запрещать** `unpack`,
    `checkout`, `reset`, `stash` — один такой агент уже стёр чужую работу.
    Красный тест во время работы такого агента — сначала проверить, не пишется
    ли файл прямо сейчас.
12. **Новая карточка результата теста** — только через `module/helpers/
    test-card.mjs` (`postTestCard`/`rollStatLine`), не `thresholdLine`.
13. **Новая книга = свои паки** (тип × источник), своя запись в `FEATURES`
    (`module/constants/features.mjs`); не подмешивать в `weapons`/`armor`.
14. **Новый блок на листе — сворачиваемый** по образцу «Импланты»; несколько
    опций — каскадным подпунктом меню, раскрытие кликом, не наведением.
15. **UI плотный:** пояснения — в подсказки (`title=`), место — под кнопки и
    числа, не под прозу.
16. **Временные эффекты:** единица времени книги выбирает механизм
    (минуты+ → `worldTime`, раунды → Duration/`game-session.mjs`,
    сцена/сессия → `flags.usageLimit`).

## 12. Первая сессия на новой площадке — минимальный порядок

1. Прочитать `AGENTS.md`, `docs/systems-map.md`, `MEMORY.md` (индекс памяти).
2. Проверить инструменты Sahara (раздел 7.1); если нет — сказать Сергею сразу.
3. `git status`, `git log origin/main..main` — сколько незашипленных
   коммитов лежит локально (фикс открытого тикета может уже быть там).
4. Сделать read-only триаж открытых задач (`node tools/sahara-tasks.mjs`):
   около трети бывали уже исправленными в `main`.
5. Только потом брать работу; в конце — по команде «Конец сессии».

Для игры: этот документ ничего не меняет в самой игре — он нужен, чтобы новый
помощник не потерял правила проекта и не повторил старых ошибок (сломанный мир
из-за неверного id, потерянные задачи, затёртая чужая работа).
