# Конец сессии

Полный протокол — в bd-памяти, не здесь:

```bash
bd recall cmd-konec-sessii
```

Прочитать его **заново** при каждом запуске, не полагаться на то, что было в
контексте сессии раньше — протокол может обновиться другой сессией между
стартом и концом (уже случалось 10.09.2026, см. историю изменений в самой
заметке и в `bd recall artifact-vedomost`).

**С 24.09.2026 (решение владельца) — ведомости нет, задачи в Sahara Studio.**
Шаг публикации «Ведомости рокового похода» и лок `wdbc-izef` из протокола
ниже ОТМЕНЕНЫ — пропускать. Вместо него последним шагом этапа 3: по каждой
задаче Sahara, которую сессия закончила, — `mcp__sahara__commentOnTask` с
«Готово: …», номером PR/коммита и строкой «Для игры:» (стадию в Done ставит
владелец, MCP этого не умеет); найденное новое — `mcp__sahara__createTask`.
Задачи, закрытые/заведённые в bd, упоминаемые в протоколе, читать как
задачи Sahara (AGENTS.md → «Трекер задач — Sahara Studio»); коммит
`.beads/issues.jsonl` нужен только если трогали лок/`testing`/память.

**С 26.09.2026 — перед этапом 3 сверить «проверено ли живьём».** Всё, что
сессия поменяла и что `live-tester` не подтвердил в Foundry, заводится в
очередь `testing` (`bd create --type=task --label=testing`, при PR —
`--external-ref gh-<N>`); без `bd` (облако) — блок «## Проверить в Foundry
(очередь testing)» в описании PR. Найденный в описании открытого PR такой
блок от облачной сессии — перенести в bd здесь же. Подробно — AGENTS.md.

Коротко, что там: три этапа — Обзор → Локальный → Удалённый. Гейт на этапе 1
(хвосты/предупреждения — если не чисто, ждать подтверждения пользователя,
дальше идти автоматически). Явный триггер вместо автозапуска (искл. —
`night-session`, см. её же п.8). Публикация «Ведомости рокового похода» —
сама сессия, последним шагом этапа 3, через лок `wdbc-izef` (образец —
`wdbc-a4l`, лок живого тестирования).

Если содержимое `cmd-konec-sessii` устарело или требует правки — менять через

```bash
bd remember "<новый текст>" --key cmd-konec-sessii
```

сохраняя прежний текст целиком и дописывая новое отдельным блоком с датой и
поводом, а не здесь: этот файл — только гарантия того, что протокол
прочитан перед выполнением, не дубликат самого протокола.
