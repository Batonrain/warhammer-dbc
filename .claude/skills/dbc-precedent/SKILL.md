# Сначала искать, потом строить

Три раза за одну сессию (31.08.2026) «новая система с нуля» оказывалась на
поверку сборкой уже существующих, но не соединённых кусков — не потому что
задачи были простыми, а потому что этот проект годами копит вокабуляр:
свойства, Черты, условия, гейты, которые кто-то завёл под один случай и
больше никто не подключил к соседнему.

Примеры того же провала (см. `docs/skill-candidates.md` — те же строки
стали основанием завести этот скилл на третьем повторе):

- **Гравитонное/Дым (wdbc-wlwf).** «Зона с готовым списком свойств» не
  потребовала новой инфраструктуры: `TERRAIN_PROPS` в
  `difficult-terrain.mjs` уже держал чекбокс «Дым или туман», а
  `DifficultTerrainBehaviorType` можно повесить сайдкаром на тот же
  Region, не сочиняя composite-behavior.
- **Gyro-Stabilized (wdbc-z56a).** Свойство «игнорирует нестабильную
  платформу, в т.ч. верхом» оказалось тем же уже существующим штрафом
  «стрельба с седла» (`#atk-mount-ranged`, wdbc-8nz6) — просто раньше
  никто не связал два текста книги друг с другом.
- **Занятость рук (wdbc-3xqh).** Independent/Wrist уже были auto-флагами
  на 0 занятых рук; хваты «П»/«Л» рукопашного уже кодировали то же самое;
  `shieldHand`/`weaponHand` уже существовали как флаги предмета (только
  для HUD-карточек); Multiple Arms — зрелый Трейт, уже растущий от
  кибернетики; `lostHandsCount`/`lostArmsCount` — уже существующие, но
  никем не читаемые условия; `attackerMount`/`speedKey` в
  `attack-dialog.mjs` уже резолвились синхронно рядом. Вся новая система
  свелась к одной функции-агрегатору поверх шести готовых кусков.

## Чек-лист перед первой строчкой кода

1. **Разбить книжный текст механики на отдельные слова-концепты** (не
   фразу целиком) и прогнать `Grep` по каждому отдельно — по-русски и по
   английскому термину, если он есть в скобках оригинала. Совпадающий по
   смыслу код часто называется не так, как ждёшь: «занимает руку» может
   лежать в коде как `grips`, `weaponHand`, `handsRequired` или вообще
   быть implicit-полем без явного имени.
2. **Проверить соседние механики той же книжной главы**, не только
   буквальное совпадение термина — свойство оружия часто оказывается
   переформулировкой уже автоматизированного соседнего свойства (Gyro-
   Stabilized ↔ штраф с седла).
3. **Погрепать существующие условия/Черты/флаги актора**, даже если они
   выглядят декоративными (использовались только для UI-подсказки или
   HUD-карточки) — декоративность не значит «нет данных», значит «данные
   есть, потребителя ещё нет».
4. **Проверить `bd list`/открытые тикеты того же лейбла** — соседняя
   параллельная сессия могла уже наполовину решить смежный кусок (см.
   `wdbc-3hxg` рядом с `wdbc-3xqh`): читать её `DESIGN`/`NOTES`, а не
   изобретать заново то же самое под другим именем.
5. Только после этого — решать, что из найденного действительно
   переиспользуется агрегатором/обвязкой, а что требует нового поля/файла.
   Если после честного поиска не нашлось НИЧЕГО — это нормальный, не
   частый исход, и тогда новая система действительно нужна с нуля.

## Чего не делать

Не считать «уже неплохо звучит по описанию» доказательством переиспользования
— перепроверять чтением самого кода (какие поля реально читает функция,
куда реально пишет), не полагаться на имя функции/комментарий в шапке файла.
Найденный кусок может оказаться декларацией без реализации (auto-флаг,
который никто не читает) — это ВСЁ РАВНО ценная находка (вокабуляр уже
согласован с остальной системой), просто обвязку придётся дописать, а не
только подключить.
