# Контент живёт в packs-src, а не в коде

Главное, что ломает старые привычки: **наполнение компендиумов при запуске мира
удалено** (этап 4 плана). Мир их больше не заполняет, файлы `module/constants/*.mjs`
данными компендиумов быть перестали. Править контент правкой библиотеки в коде
теперь бессмысленно — изменение никуда не попадёт.

## Источник истины

| Что | Где |
| --- | --- |
| Библиотеки предметов и акторов | `packs-src/<пак>/` — JSON по файлу на документ |
| Книги | `packs-src/books/<книга>.json` — по файлу на книгу |
| Скомпилированный LevelDB | `packs/` — **не в git**, собирается |
| Список паков | `system.json` → `packs` (сборка берёт список отсюда, не из папки) |
| Раскладка по папкам боковой панели | `system.json` → `packFolders` |

## Две команды

```bash
npm run packs:build
```

```bash
npm run packs:unpack
```

**Порядок безопасный: сначала `packs:unpack`, потом `git diff`, потом всё остальное.**
Сборка стирает папку пака целиком — правки, сделанные руками в Foundry и не снятые
через `packs:unpack`, она потеряет. После клона `packs:build` нужно выполнить один
раз, иначе Foundry увидит пустые компендиумы.

## Что проверяет CI

Круговорот: собрать компендиумы из исходников → извлечь обратно → `git diff
--exit-code -- packs-src`. Расхождение хоть на байт — красный пул-реквест. Это ловит
и потерю содержимого при сборке, и расхождение двух инструментов между собой.

## Правила, которые легко нарушить по незнанию

- **`_id` — РОВНО 16 символов `[A-Za-z0-9]`.** Не «до 16». Придуманный руками
  говорящий id (`LocusHeraldFld1`, `DreadTalentsFld` — по 15) проходит ВСЕ гейты:
  `npm test`, `npm run lint`, `npm run packs:build` зелёные. Ломается только живой
  мир, и насмерть: `DataModelValidationFailure … is not a valid 16-character
  alphanumeric ID`, клиент виснет с пустой страницей и `game.ready === false`, а в
  логах сервера при этом «Launching World | Complete» — оттуда не видно. Берите
  случайную строку ровно 16 символов и помните, что id живёт в четырёх местах: `_id`,
  `_key` (`!items!<id>`, `!folders!<id>`), имя файла и поле `folder` у детей
  папки.
- **Ссылки `@UUID` в исходнике книг не хранятся** — сборка расставляет их сама по
  названиям предметов. Сохранённая ссылка попала бы внутрь новой при следующей сборке.
- **Имена файлов в `packs-src/` обрезаны намеренно** (`tools/unpack.mjs`, `NAME_LIMIT`):
  у каталогов снят суффикс-id, название обрезано до 40 символов — иначе кириллические
  пути пробивают потолок Windows в 260 байт и `git checkout` падает с «Filename too
  long». Полное название лежит внутри JSON. Не «чинить» короткие имена.
- **Новый пак** добавляется в `system.json` дважды: в `packs` (иначе не соберётся —
  список берётся из манифеста) и в нужную подпапку `packFolders` по книге-источнику.
  Верхняя папка — «Doom Crusade», организована по книгам-источникам; плоскую общую
  папку не заводить.
- **Поле «книга-источник» — `system.bookSource`, а не `system.source`.** У Черт
  `source` означает механическое происхождение, у Происхождений — «выдано системой
  Происхождений». Разные смыслы, похожие имена.
- **Доступность = Редкость = «RX» — одна и та же сущность под тремя именами.**
  Поле в схеме — `system.availability` (подписано в листе «Доступность»), в тексте
  книг и в разговоре игроков то же самое зовут «Редкость» или сокращённо «RX», где
  X — уровень. Хранится как знаковый модификатор (`AVAILABILITY`,
  `module/constants/items.mjs`: −5 «Повсеместно» … 0 «Дефицит» … +5 «Уникально»), не
  прямым числом RX — при переносе значения из книги/просьбы игрока сверяться с этой
  таблицей, не считать «R8» напрямую равным `availability: 8`.
- **При расхождении текста между паком и кодом прав пак** — его видят игроки, и после
  этапа 4 он и есть источник истины.

## Честность цитирования книг

Ссылка на книгу проверяется по `packs-src/books/*.json` (дерево `entries[].pages[]`,
у страницы есть `pdfPage` и `html`) — грепом по точной внутрикнижной терминологии, а
не доверием к комментарию в шапке файла. Если содержимое не находится ни в одной
книге, пишем «Домашнее правило (не из официальной книги)», а не выдумываем
правдоподобное название.

## Релиз

`version` в `system.json` перезаписывается при сборке, источник истины — git-тег,
руками файл не править. Выпуск — **Actions → Release → Run workflow**.

## Ловушка: id папки как ДАННЫЕ, не только структура

`kind:"equipment"`+`equipMode:"choice"` (Конструктор, «выбор оружия/брони по
фильтру») хранит `equipWeaponType` — это `_id` РЕАЛЬНОЙ папки компендиума
`weapons`, а не просто путь для UI. У девяти-одиннадцати архетипов Астартес/
Людей этот id указывал на «Азуриане → Рукопашное → Цепное/Силовое» вместо
«Имперское → Рукопашное → Цепное/Силовое» — Обозреватель показывал ТОЛЬКО
эльдарское цепное оружие человеческому/астартовскому архетипу (баг-репорт
20.08.2026, wdbc-2ot). Похоже на автоматический перегон текста в Механику,
искавший папку по ИМЕНИ («Цепное») без учёта ветки фракции и взявший первое
совпадение в алфавитном порядке («Аз…» раньше «Ас…»). `coreWeaponTypeFolders()`
(`module/apps/compendium-browser.mjs`) сама ограничена ТОЛЬКО веткой
«Имперское» — если хранимый id указывает мимо нёе, `describeMechEntry` не
находит имя для подсказки («Снаряжение: выбор — «Оружие» ()» — пустые скобки)
одновременно с неверной фильтрацией: оба симптома лечатся одной правкой
данных. Проверять так: найти `_Folder.json` нужной папки в `packs-src/weapons/
<Ветка>/.../_Folder.json`, сверить `_id` со значением `equipWeaponType` записи.
