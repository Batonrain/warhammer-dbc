# Тестирование

Правило и порядок действий — в bd-памяти, прочитать первым делом, до всего
остального:

```bash
bd recall cmd-testirovanie
```

Дальше выполнять ровно то, что там написано: как собрать задачи, как вызывать
`live-tester`, что делать с найденными багами, когда закрывать
проверенную задачу, когда обновлять статус в PR.

**Поверх `cmd-testirovanie`, с 21.11.2026 (решение владельца) — два правила о проверках.**
1. QA-прогон («Тестирование», `live-tester`) берёт ВСЮ открытую очередь
   `testing` в bd и ВСЕ задачи Studio в статусе «На проверке» (In Review), а не
   только проверки свежих PR.
2. Кто ставит задачу в «На проверке», сразу заводит к ней пункт проверки:
   задачу `testing` в bd + «[Проверить #N] …» в Studio; без bd (облако) — пункт
   в блоке «## Проверить в Foundry (очередь testing)» описания PR.
«Готово» ставится по живой проверке в Foundry; слияния PR не ждать — его
делает другой человек без доступа к трекеру.

Если содержимое правила `cmd-testirovanie` устарело или требует правки —
менять через `bd remember "<новый текст>" --key cmd-testirovanie`, а не
здесь: этот файл — только гарантия того, что правило прочитано перед началом,
не дубликат самого правила.
