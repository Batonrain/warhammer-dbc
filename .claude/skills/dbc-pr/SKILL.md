# Пул-реквесты без gh

**Устарело с 01.09.2026.** Предпосылки этого скилла больше не верны: `gh`
теперь установлен и авторизован (`gh auth status` — аккаунт `Derbius-D`), ветки
`origin/Derbius` и единого долгоживущего PR больше нет — см. `dbc-workflow`,
раздел «Git и трекер»: каждая сессия сама заводит `git worktree`, свою ветку
`pr/<тема>` и открывает СВОЙ PR через `gh pr create --base main --head
pr/<тема>`. Обновление описания уже открытого PR тоже проще делать штатно —
`gh pr edit <N> --body-file <файл>` (или `--body "текст"`), без токена из
Credential Manager и без этого скрипта. Оставлено ниже как рабочий запасной
путь на случай, если `gh` вдруг снова окажется недоступен — не как основной
процесс.

## Прежний контекст (до 01.09.2026)

`gh` в этом окружении не установлен, а `main` на GitHub защищена и принимает только
пул-реквесты. Работа уезжает в `origin/Derbius`, и её описывает один долгоживущий PR
(`Derbius → main`), в который дописываются разделы по мере закрытия кусков работы.

## Токен

Отдельный секрет заводить не нужно: PAT уже лежит в Git Credential Manager, тем же
пользуется `git push`. Достаётся так и **в командную строку не попадает** — только
через stdin/stdout процесса:

```bash
printf 'protocol=https\nhost=github.com\n\n' | git credential fill
```

В ответе строка `password=` — это и есть токен для `Authorization: token …`.

## Команды

Посмотреть текущее описание PR текущей ветки:

```bash
python .claude/skills/dbc-pr/update-pr.py --show
```

Дописать или обновить раздел (текст из файла или со stdin):

```bash
python .claude/skills/dbc-pr/update-pr.py --title "Книга «Машины»" --file раздел.md
```

Переименовать сам пул-реквест (это НЕ заголовок раздела):

```bash
python .claude/skills/dbc-pr/update-pr.py --pr-title "Новое имя PR"
```

`--pr-title` работает и сам по себе, и вместе с `--title`/`--file`. Нужен потому, что
PR тут долгоживущий: имя, данное ему в первый день, к десятой теме врёт — «Миньоны,
верховой бой и Оружие Наследия» на ветке, где давно ещё Конструктор, книга Машин,
Хаос и Дредноуты.

Скрипт сам определяет репозиторий из `origin`, ветку из HEAD и номер открытого PR по
ветке; при необходимости всё это переопределяется — `--repo`, `--branch`, `--pr`.

## Как устроена запись

**Раздел ищется по своему заголовку `## <title>` и заменяется целиком** — до следующего
заголовка того же уровня. Поэтому повторный запуск после новой порции работы обновляет
тот же блок, а не плодит копии, и чужой текст описания не затрагивается. Если раздела
ещё нет, он дописывается в конец.

Заголовок — ключ. Для другой книги или другого куска работы берите другой заголовок,
иначе перезапишете предыдущий раздел.

## Ловушки

- **`git` не в PATH у PowerShell** — он приходит с GUI-клиентом Fork
  (`%LOCALAPPDATA%\Fork\gitInstance\<версия>\cmd\git.exe`). Скрипт ищет его сам:
  сначала PATH, потом установку Fork по маске, поэтому версия в пути не мешает.
- **Номер PR не хардкодить.** Он находится запросом по ветке; `--pr` нужен, только
  когда открытых PR несколько или ветка чужая.
- **Пуш сначала, описание потом.** Описание PR не проверяет, что коммиты доехали:
  сперва `git push origin Derbius`, затем правка текста.
- Токен из credential manager даёт полный доступ к репозиторию — ничего, кроме
  запрошенного действия с PR, им не делать.
