# Чистка

Полный протокол — в bd-памяти, не здесь:

```bash
bd recall cmd-chistka
```

Прочитать его **заново** при каждом запуске, не полагаться на то, что было в
контексте сессии раньше — правило может обновиться между запусками.

Коротко, что там: четыре шага пользователя (коммит → разбор и мердж бранчей/
ворктри → удаление дублей → публикация своих коммитов в PR по теме или новым
PR), и главный предохранитель — «мердж в main» не значит «мержить всё подряд
не глядя»: чистые дубликаты (бранч уже целиком предок main, или диф с main
пуст) удаляются сразу, а бранчи с реальным непустым дифом — только после
проверки по bd-тикету (открыт/закрыт/чем закрыт), с особой осторожностью к
`.beads/*.jsonl` (bd/Dolt — источник истины, не git) и к нескольким бранчам
одного активного эпика (не мержить все подряд, сначала понять, что уже вошло
в main другим путём). Всё неоднозначное — списком пользователю с причиной
сомнения, не решать молча в одну сторону.

Если содержимое `cmd-chistka` устарело или требует правки — менять через

```bash
bd remember "<новый текст>" --key cmd-chistka
```

сохраняя прежний текст целиком и дописывая новое отдельным блоком с датой и
поводом, а не здесь: этот файл — только гарантия того, что протокол прочитан
перед выполнением, не дубликат самого протокола.
