Ты — исполнитель одного шага задачи **wdbc-kuun**: карточки чата собирались вручную в 92 файлах (237 вызовов `ChatMessage.create`, 232 самодельных блока `wh-roll-result`), и их переводят на общий сборщик по подсистемам.

С **wdbc-fyvv** (16.09.2026) общая форма строки Порога — плашка **Бросок / Режим / Порог** (`rollStatLine()`, см. ниже), не текстовая строка с «→». Вся система уже переведена на неё; новых `thresholdLine`-строк не заводить.

Общий регламент — `AGENTS.md` и скилл `dbc-workflow`. Здесь только то, чего в них нет.

## Твоя рамка

Тебе дают **список файлов или папку**. Не выходи за него: увидел рядом другой дефект — заведи `bd create`, а не чини попутно. Несколько таких агентов работают параллельно, и чужая правка в твоём диффе делает оба нечитаемыми.

**Никогда не трогай файл вне своего списка.** Если правка требует изменить общий модуль (`module/helpers/test-card.mjs`, `module/rules/roll-mods.mjs`) — остановись и скажи об этом в отчёте, не правь: его же может править соседний агент.

## Инструмент

`module/helpers/test-card.mjs` — прочитай его целиком перед работой. В нём:

- `testCardHtml({prelude, icon, title, actorUuid, classes, threshold, lines, rv, dice, rerollNote, critLine, outcome, sections})` — чистая функция разметки. Порядок строк фиксированный: предисловие, шапка, Порог, свои строки, бросок, кубики, переброс, крит, исход, свои блоки. Пустые куски не рисуются вовсе, включая шапку без иконки и заголовка. `prelude` — блок ВЫШЕ шапки («Приём: Замахнуться», чип Орды); `classes` — доп. классы корня рядом с `wh-roll-result`, когда за них цепляется вёрстка подсистемы (`sq-chat`, `wh-daemon-card`, `horde-dmg`, `wv-tier-*`);
- `rollStatLine({prefix, label, base, parts, threshold, rv, rerollNote})` — **основной инструмент для строки Порога с wdbc-fyvv.** Строит плашку `Бросок / Режим / Порог` одним рядом ячеек (та же форма, что у карточки атаки). `label` подписывает ячейку Режим (характеристика/навык — «Ag», «WS», «Command(F)»; можно и описательный текст, если короткого имени нет, тогда он идёт в `base` строкой, а `label` не передаётся). `base`+`parts` (разбивка «характеристика + модификаторы») уходят во всплывающую подсказку (`title=`) ячейки Порога, НЕ в видимый текст. `threshold`/`rv` — числа (или `null`, тогда ячейки нет: годится для «Порог не сравнивается» или «бросок без цели»). При переезде на неё верхнеуровневый `rv,` рядом с `threshold:` в `testCardHtml`/`postTestCard` убирается — он живёт только внутри `rollStatLine`;
- `thresholdLine({prefix, label, base, parts, threshold})` — **устаревший путь, новых вызовов не заводить.** Текстовая строка Порога без плашки; жива только ради обратной совместимости и редких карточек без Броска в принципе;
- `statLine([{label, value, note, title}])` — низкоуровневая «статлиния» (ячейки
  «подпись/значение» в ряд), на которой построена `rollStatLine`. Обращаться к
  ней напрямую нужно, только если контракт `rollStatLine` не подходит (2+
  независимых Порога сразу — см. пример walker.mjs ниже);
- `head` у `testCardHtml` — блоки сразу под шапкой, ДО Порога/статлинии: у
  карточки атаки там Особые Свойства, Качество, «Хват и приёмы»;
- `outcomeHtml(success, text)` — успех/провал одним классом;
- `postTestCard(actor, card, {rolls, sound, flags, speaker, whisper})` — публикация:
  `getSpeaker`, `applyRollMode` и флаги карточки внутри. `speaker` нужен
  карточкам, которые говорит не персонаж (системные уведомления от «Системы»),
  `whisper` — тем, что видит только владелец и ГМ.

Образцы уже переведённых карточек, на которые надо равняться: `module/combat/defense.mjs` (Уклонение, Парирование, Сжатие — `rollStatLine` с числовой базой), `module/sheets/squad-sheet.mjs` (`base` как строка «Командир: Имя», короткого label нет), `module/combat/walker.mjs::performWalkerDodge` (комбинированный тест — ДВА независимых Предела разом, в `rollStatLine` не сводится: плашка только с `rv`, разбор — текстом рядом), `module/apps/infoguard.mjs`.

## Порядок

1. **Раздели тесты и не-тесты.** Карточка теста несёт бросок и Порог. Уведомление («зона размещена», «истёк срок», «запрос теста») — не карточка теста: его НЕ переводи, а пометь коротким комментарием в коде, почему. Признак для поиска: есть ли рядом `roll-dice`.
1а. **Ищи ВСЕ вхождения в файле, не только первое.** Регулярно повторяющийся дефект (wdbc-fyvv, 16.09.2026, случилось минимум в 7 файлах подряд — `walker.mjs`, `formation-sheet.mjs`, `daemon-sheet.mjs`, `squad-sheet.mjs`, `ship-sheet.mjs`, `tabs/psychic.mjs`, `movement-actions.mjs`): в одном файле бывает НЕСКОЛЬКО разных функций с одинаковым ручным паттерном строки Порога — один поправили, соседние (по 2-7 штук) пропустили, потому что искали по комментарию/примеру, а не по всему файлу. После правки каждого файла своего списка — `grep -c "→ Порог"` (или другой признак ручной строки Порога, смотря что ищешь) должен дать `0`; не считать файл законченным по одному найденному месту.
2. **Не меняй вид без нужды.** Перевод обязан оставить карточку такой же, какой была: те же строки, тот же порядок, те же подписи. Если вид всё-таки меняется (например, слагаемые Порога переезжают в скобки к общему формату) — скажи об этом в отчёте отдельной строкой, это не мелочь.
3. **Достань подписи модификаторов.** Частый дефект этой задачи: `ruleMods.parts` собран, Порог посчитан верно, а в карточке стоит голое число. Проверь каждый файл своего списка: есть `collectTestMods`/`autoTestMods`, но нет ни одного `.parts` — значит модификатор посчитан и потерян по дороге к игроку. Подставь его.
4. **Сверь показанный Порог со считанным.** Второй дефект того же рода: карточка пишет `Порог: ${wp}`, а успех сравнивается с `wp + модификаторы`. Игрок видит не то число, по которому его судили.
5. **Убери осиротевшее.** После перевода `const rollMode = ...` и локальные `const messageData` обычно больше не нужны — их поймает lint, но лучше убрать сразу.
6. Гейты, с приведением вывода, а не памяти о нём:

```bash
npm test
npm run lint
```

`npm run packs:build` не нужен: карточки не трогают `packs-src/`.

Если полный `npm test` падает по `Test timed out` — это известная хрупкость (`wdbc-lxyl`), а не твоя поломка: перепроверь тем же прогоном с `npx vitest run --testTimeout=120000`. Красным считается только содержательное падение.

## Чего не делать

- **Не «улучшать» тексты карточек.** Формулировки книги и подписи — не твоя область. Меняешь только способ сборки.
- **Не трогать расчёт.** Если Порог считается неверно — это находка, `bd create`, а не правка на месте.
- **Не «улучшать» состав карточки атаки.** Она большая по делу: попадания по
  локациям, свойства оружия, урон, поглощение, кнопки применения эффектов.
  Переводится она тем же сборщиком (для неё и заведены `statLine` и `head`),
  но состав блоков и их порядок — не твоя область.
