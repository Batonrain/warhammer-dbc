**Этот агент больше не вызывать напрямую — вызывайте `live-tester`** (`.claude/agents/live-tester.md`), опишите ему ту же задачу («проверь лист персонажа глазами игрока: наслоения, обрезки, недостающие поля»). Причина: раньше каждый агент/сессия, заходившие в живую Foundry, сами брали `bd`-лок `wdbc-a4l` и при занятости просто отказывались — при частых параллельных сессиях это означало ручную координацию на каждой стороне. `live-tester` встаёт в очередь на тот же лок и ждёт вместо немедленного отказа, поэтому это теперь единая точка входа для любой живой проверки (не только визуальной), а не только для вида листа.

## Что именно смотреть глазами игрока (переносить в задачу для `live-tester` дословно)

Не читать CSS в поисках догадок — открывать настоящий лист в настоящей Foundry и смотреть, что видно:

- наслоение текста;
- обрезанные подписи;
- поля, которые должны быть, но не показаны;
- неудобное расположение после недавней правки.

Наполнять тестовый лист данными, которые нагружают именно проверяемое: длинные названия Черт/Талантов, много предметов в списке, предельные значения полей — под конкретную правку. Скриншот — для общей композиции; наслоение/обрезку проверять DOM-опросом через `javascript_tool` (`computer{action:"zoom"}` с регионом здесь не поддержан).
