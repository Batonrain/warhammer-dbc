## Порядок

1. `git diff main...HEAD` и `git diff --stat` для обзора.
2. Релевантные разделы `docs/architecture-plan.md`.
3. Три гейта: `npm test`, `npm run lint`, `npm run packs:build`. Красное — стоп-фактор, дальше можно не смотреть.
4. Разбор дифа по чек-листу.

## Чек-лист

**Против плана**

- Новое ветвление по расе, фракции, архетипу, дисциплине **в коде** вместо записи в `module/rules/`? Это движение против плана.
- Новое правило без тестов? Правило без теста — незакрытая задача.
- Новые читатели `system.effects.*`? Это уходящий формат, заводить их нельзя.
- Поля типа описаны в `template.json` вместо `module/data/`? Запись в `template.json` должна остаться пустой.

**Смертельное для живого мира** — проверять всегда, даже если диф маленький

- `_id` новых записей — **ровно 16 символов** `[A-Za-z0-9]`? Все три гейта на 15 символах зелёные, а мир `iz-pepla` умирает насмерть с `DataModelValidationFailure`. Проверь `_id`, `_key`, имя файла и поле `folder` у детей папки.
- Флаг `warhammer-dbc.migratedEffect` не поставлен предмету, механику которого эффект не выражает? Это убивает механику с обеих сторон. Сверься с `LEGACY_ONLY_KEYS`.
- Изменилась схема — нужен ли починочный проход для живых миров? У игроков предметы лежат снимками на акторах, пак их не догонит. Миграции идемпотентны и живут в `module/migrations/`.
- Эффекты целятся в ключи из `module/constants/effect-keys.mjs`? Путь мимо реального поля ошибки не даёт — эффект молча ни на что не влияет.
- Фаза `initial`/`final` выбрана по `expectedPhase(ключ)`, а не по вкусу?

**Взаимодействие с другими системами** — диф трогает больше одной подсистемы разом (например, новый предмет одновременно цепляет Конструктор, эффекты и миграцию)

- Новая запись Конструктора и запись эффектов на одном ключе одновременно? Это удвоение бонуса — считать источники по ключу (`module/constants/effect-keys.mjs`), не по числу записей.
- Правка тянет за собой соседнюю подсистему (Конструктор → миграция, эффекты → откат при удалении предмета), а задета только одна сторона? Откат/чтение должны быть симметричны правке.
- Новая структура (запись Конструктора, тип предмета, паттерн правила) списана с ближайшего существующего аналога, а не изобретена заново? Разное решение одной и той же задачи в соседних местах — повод спросить «почему тут иначе», не пропускать молча.

**Контент**

- Правки в `packs-src/`, а не в `packs/`? `packs:build` прогонялся?
- Разбор русского текста регулярками: нет ли `\w` или `\b` там, где ожидается кириллица? Регулярка не упадёт — запись тихо уедет в «нераспознанное».

**Гигиена**

- Правили то, что просили? Попутные починки в диффе — это бида, а не бонус.
- Комментарии на русском и объясняют **почему**, а не пересказывают код?
- Терминология совпадает с уже принятой в проекте? Проверь `grep`-ом новые термины.
- Затронуты расчёты на акторе (`module/documents/actor.mjs`)? Стендом они не покрыты — в отчёте должно быть сказано, что смотреть в живой игре.

## Отчёт

Сортируй: **блокеры → важное → придирки**. Каждая находка — файл, строка, что не так, чем грозит.

Не выдумывай проблемы ради объёма. Диф чистый — так и скажи, «блокеров нет». Честный пустой отчёт полезнее списка выдуманных замечаний. Но и не пропускай реальное ради вежливости.
