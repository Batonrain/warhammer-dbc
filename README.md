# Warhammer DBC

Система для Foundry VTT по Warhammer 40k в редакции DBC (Doom Black Crusade). Объединяет материал Rogue Trader, Dark Heresy и смежных линеек.

## Установка

В Foundry VTT: **Game Systems → Install System → Manifest URL**, вставьте ссылку:

```
https://github.com/Batonrain/warhammer-dbc/releases/latest/download/system.json
```

Ссылка постоянная: она всегда ведёт на последний выпущенный релиз. Обновления Foundry подхватит сам.

## Совместимость

Foundry VTT версии 13. Более ранние версии не поддерживаются.

## Состав

| Путь | Что внутри |
| --- | --- |
| `warhammer-dbc.mjs` | точка входа системы |
| `module/` | листы, боевая логика, документы, миграции, хуки |
| `templates/` | Handlebars-шаблоны |
| `styles/` | CSS |
| `lang/` | локализация |
| `packs-src/` | содержимое компендиумов в JSON — источник истины |
| `packs/` | скомпилированные компендиумы (LevelDB), собираются из `packs-src/` |
| `assets/` | иконки, изображения тарот-карт, схемы тела |

PDF правил в репозиторий не входят.

## Разработка

```bash
git clone https://github.com/Batonrain/warhammer-dbc.git
```

Дальше нужна символическая ссылка из папки данных Foundry на клон репозитория.

Windows (PowerShell от администратора):

```powershell
New-Item -ItemType SymbolicLink `
  -Path "$env:LOCALAPPDATA\FoundryVTT\Data\systems\warhammer-dbc" `
  -Target "C:\путь\к\warhammer-dbc"
```

Linux / macOS:

```bash
ln -s /путь/к/warhammer-dbc ~/.local/share/FoundryVTT/Data/systems/warhammer-dbc
```

После этого Foundry увидит систему, и правки в коде применятся после перезагрузки мира.

### Компендиумы

Содержимое компендиумов лежит в `packs-src/` в JSON: библиотеки предметов и акторов — по файлу на документ, книги — по файлу на книгу. Папка `packs/` с базами LevelDB в git не входит, её собирает команда:

```bash
npm run packs:build
```

После клона репозитория её нужно выполнить один раз, иначе Foundry увидит пустые компендиумы. В релизе сборку выполняет CI.

Правки содержимого делаются либо прямо в JSON, либо в Foundry — тогда их нужно снять обратно в исходник:

```bash
npm run packs:unpack
```

Сборка стирает папку пака целиком, поэтому правки, сделанные в Foundry и не снятые через `packs:unpack`, она потеряет. Порядок безопасный: сначала `packs:unpack`, потом `git diff`, потом всё остальное.

Ссылки `@UUID` в тексте книг в исходнике не хранятся: сборка расставляет их сама по названиям предметов из остальных компендиумов.

Пул-реквест проверяется круговоротом: CI собирает компендиумы из исходников, извлекает обратно и падает, если результат разошёлся с `packs-src/`.

### Вклад в проект

1. Сделайте форк и ветку от `main`.
2. Проверьте изменения в живой Foundry перед отправкой.
3. Откройте pull request с описанием, что и зачем меняется.

## Релизы

Релиз собирается автоматически при вливании изменений в `main`. Отдельных действий не требуется: workflow берёт последний тег, поднимает patch-версию, ставит новый тег и публикует `system.json` и `system.zip` в GitHub Release. Manifest URL при этом не меняется.

Чтобы поднять minor или major, добавьте в заголовок PR метку:

| Заголовок PR | Результат от v0.1.4 |
| --- | --- |
| `Фикс броска на повреждение` | v0.1.5 |
| `Лист техники #minor` | v0.2.0 |
| `Новая модель данных #major` | v1.0.0 |

Метка ищется в сообщении коммита слияния, куда GitHub подставляет заголовок PR. Регистр не важен.

Релиз не собирается, если PR затрагивает только `README.md`, `LICENSE`, `.gitignore`, `.gitattributes`, `.github/`, `books/`, `docs/`, `test/`, `package.json`, `package-lock.json` или `eslint.config.mjs`. Правка документации не должна поднимать всем игрокам обновление на 38 МБ.

Правки `packs-src/` и `tools/` релиз собирают: первое — содержимое компендиумов, второе — то, чем они собираются.

Выпустить версию вручную можно на вкладке **Actions → Release → Run workflow**, выбрав тип инкремента.

Поле `version` в `system.json` перезаписывается при сборке. Источник истины — git-тег, править файл вручную не нужно.
